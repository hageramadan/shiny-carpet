# Shiny Carpet — Shiny Carpet

مشروع مستقل لتصميم موقع غسيل السجاد والبطاطين، عربي RTL باستخدام Next.js App Router وTypeScript وTailwind CSS وreact-icons وخط Cairo محلي.

## التشغيل

```sh
npm install
npm run dev
```

المعاينة: http://localhost:3000. على Windows يمكن تشغيل start-dev.cmd مباشرة بعد تثبيت المكتبات. لو أمر npm غير متاح استخدم: node node_modules/next/dist/bin/next dev --port 3000

```sh
npm run typecheck
npm run build
npm start
```

## البيانات الة

السلة مرتبطة بواجهات الباك إند وتتطلب تسجيل الدخول، ولا تُخزن في localStorage. العناوين مرتبطة بواجهات الباك إند، وسجلات الطلبات القديمة فقط ما زالت محلية. إنشاء الطلب والدفع غير متاحين لحين توفير واجهاتهما. تسجيل الدخول والتسجيل والتحقق وإعادة إرسال الرمز والخروج مرتبطة الآن بـAPI المصادقة، وإرسال SMS يتولاه الباك إند. الملف الشخصي المعروض يُستعاد من جلسة التحقق، ولا يكفي سجل محلي قديم لتسجيل الدخول. قسم خدماتنا وأسعار المنتجات من API شايني كاربت، والبحث عن الأماكن خاص بالعناوين. لا توجد تقييمات أو أرقام عملاء وهمية.

## SEO قبل النشر

عناوين وأوصاف صفحات الخدمة مع canonical وOpen Graph وTwitter، HTML عربي على الخادم وsitemap.xml وrobots.txt. صفحات الحساب والشراء والتتبع مستبعدة من الفهرسة. انسخ .env.example إلى .env.local وغيّر NEXT_PUBLIC_SITE_URL للدومين الحقيقي قبل البناء والنشر. ترتيب البحث يعتمد على المحتوى الحقيقي والدومين والأداء والربط؛ لا توجد ضمانات ترتيب.

## ربط المصادقة والجلسة

- العمليات هي `register` و`login` و`verify` و`resend` و`logout`. طلبات المتصفح تذهب مباشرة إلى `https://admin.shinycarpet-sa.com/api/auth/{action}` وتظهر بهذا الرابط في Network، مع `Accept-Language: ar`.
- الرقم يُفصل إلى `phone` بدون رمز الدولة و`country_code` مثل `+20`. لا توجد عملية `exist`؛ أخطاء الحساب تأتي من الباك إند.
- التسجيل والدخول يبقيان الحساب في انتظار التحقق. بعد نجاح OTP تُحفظ بيانات المستخدم والتوكن في `localStorage` وتستمر بعد إغلاق التبويب وفتح الموقع مجددًا، حتى الخروج أو انتهاء صلاحية التوكن. تغييرات الجلسة تتزامن بين التبويبات. تبقى مسودات OTP المؤقتة في sessionStorage. صلاحية التوكن يحددها الباك إند.
- الخروج يرسل `Authorization: Bearer <token>` ثم يمسح الجلسة والمسودة عند النجاح أو 401. فشل الشبكة يبقي الجلسة لإعادة المحاولة. عرض السلة يمسح عند الخروج، وتبقى سلة الحساب محفوظة لدى الباك إند.
- `lib/auth/contracts.ts` يتحقق من المدخلات والردود، و`lib/auth/session.ts` يدير تخزين الجلسة، و`lib/auth/client.ts` يرسل الطلبات المباشرة ويرفق التوكن بالطلبات المحمية. إعادة الإرسال تنتظر ٦٠ ثانية بعد نجاح الإرسال.
- الرابط الأساسي هو `NEXT_PUBLIC_API_BASE_URL` أو رابط الإدارة الافتراضي وينتهي بـ`/api`. تغيير المتغير يحتاج إعادة البناء. لا توضع توكنات في المتغيرات العامة.

الاختبارات: `npm run test:auth` و`npm run test:phone` و`npm run test:api`. اختبار `npm run test:auth:browser` يحتاج Playwright وEdge وخادم `node tests/fixtures/auth-api.cjs` على 4109 والتطبيق على 3107. يمكن ضبط `PLAYWRIGHT_MODULE_PATH`. الاختبار يعترض طلبات دومين الإدارة ويستخدم خادمًا محليًا دون إرسال SMS.

## API الملف الشخصي

صفحة `/profile` تجلب البيانات من `GET https://admin.shinycarpet-sa.com/api/profile` وتعرض حالات التحميل والخطأ وإعادة المحاولة. العمليات تستخدم التوكن الحالي في `Authorization: Bearer` و`Accept-Language: ar` وتظهر مباشرة على دومين الإدارة في Network.

حفظ الاسم والهاتف والصورة يرسل `POST /profile` باستخدام `FormData` بالحقول `name` و`phone` و`country_code` و`image` عند اختيارها. المتصفح يحدد حد multipart تلقائيًا. الصور المقبولة JPG وPNG وWebP حتى ٥ ميجابايت؛ صور العرض مسموحة من `/storage/profile/` على دومين الإدارة فقط. الملف `lib/profile.ts` يتحقق من شكلي الرد `status: success` و`result: true` ويحدث بيانات العرض داخل الجلسة دون تغيير التوكن.

عند تغيير الهاتف تُحفظ مسودة الرقم الجديد في جلسة التبويب وتظهر خانات OTP داخل صفحة الحساب. يظل الرقم السابق معتمدًا حتى نجاح `POST /profile/verify` بالحقول `phone` و`country_code` و`code`؛ المسودة تستمر بعد تحديث الصفحة. لا يستخدم هذا التدفق واجهة OTP تسجيل الدخول. لم تُضف إعادة إرسال لتغيير الهاتف لعدم توفير واجهتها.

حذف الحساب يستخدم `DELETE /profile` بعد تأكيد داخل الصفحة. النجاح يمسح جلسة الدخول ومسودات التحقق ويوجه إلى الدخول، والفشل يبقي الجلسة لعرض الخطأ وإعادة المحاولة. لا تنفذ الاختبارات حذفًا أو إرسال SMS على حساب حقيقي.

اختبارات الملف: `npm run test:profile`، واختبار الواجهة `npm run test:profile:browser` يحتاج Edge وPlaywright والتطبيق على 3107. يعترض الاختبار طلبات الملف بالكامل ويستخدم ردودًا محلية.

## حقل الهاتف المشترك

`components/forms/PhoneInput.tsx` يُستخدم في تسجيل الدخول والتسجيل والملف الشخصي وإتمام الطلب. قائمة الدولة متصلة بحقل الرقم وعلى يساره دائمًا باستخدام اتجاه LTR داخل المكوّن. القائمة تضم السعودية ومصر والإمارات والكويت وقطر فقط، مع أسماء الدول بالعربي وأعلامها ودعم لوحة المفاتيح والموبايل. الأعلام الخمسة تُستورد منفردة من `country-flag-icons/react/3x2` كعناصر React محلية لتقليل حجم التحميل وعدد العناصر عند فتح القائمة، والقائمة من `@radix-ui/react-dropdown-menu` بوضع غير حاجب، فلا تقفل تمرير الصفحة ولا تغير هوامشها عند الفتح.

المكوّن يدعم `value` و`onChange` أو `defaultValue`، و`name` و`form` لربطه بالنماذج، و`required` و`disabled` ورسائل التحقق. السعودية هي الافتراضية، ويمكن تغييرها عبر `defaultCountry`. القيمة المحفوظة رقم دولي موحد مثل `+966551234567` في حقل مخفي، بينما حقل الإدخال يعرض الرقم المحلي دون تكرار رمز الدولة. `lib/phone.ts` يجمع تحويل الأرقام العربية والفارسية والتنسيق والتحقق من طول الرقم المناسب للدولة. التحقق من صيغة الهاتف لا يرسل SMS ولا يثبت ملكية الرقم.

## العناوين والخريطة

العناوين في `/addresses`، والإضافة في `/addresses/new`، والتعديل في `/addresses/[id]/edit`. تُجلب من API الحساب، ولا تقرأ أو تحفظ في localStorage. تحفظ الإحداثيات والمبنى والدور والشقة والملاحظات على الباك إند. تظهر نفس القائمة في الملف الشخصي والشراء. اختيار عنوان من صفحة الشراء لا يغيّر علامة is_default على السيرفر؛ لا توجد واجهة تعيين افتراضي ضمن الواجهات المقدمة.

الخريطة تستخدم Leaflet وبيانات OpenStreetMap، والبحث عبر Photon من مسار `/api/locations`. البحث يحدث عند الضغط على زر البحث، وتُخزّن نتائجه مؤقتًا مع تقليل معدل الطلبات. يمكن تغيير خادم Photon عبر `GEOCODING_BASE_URL`. الخادم العام مناسب للمعاينة محدودة الاستخدام ولا يضمن التوافر: https://github.com/komoot/photon#demo-server. استخدام خرائط OpenStreetMap يخضع لسياسة البلاطات: https://operations.osmfoundation.org/policies/tiles/.

الموقع الحالي يحتاج إذن المتصفح، ويعمل عبر HTTPS أو localhost. لا يُطلب الموقع تلقائيًا؛ يمكن البحث عن أي مكان أو اختيار نقطة وسحب العلامة. راجع تفاصيل العنوان المقترحة قبل الحفظ، خصوصًا رقم المبنى والدور والشقة. هذه واجهة ة؛ لا تُنشئ طلب توصيل حقيقيًا.

## API الخدمات والمنتجات

قسم خدماتنا وقائمة المنتجات يجلبان البيانات مباشرة من المتصفح، لذلك تظهر الطلبات في Network → Fetch/XHR:

- GET https://admin.shinycarpet-sa.com/api/categories
- GET https://admin.shinycarpet-sa.com/api/products/category/{categoryId}
- GET https://admin.shinycarpet-sa.com/api/products/{productId}
- POST https://admin.shinycarpet-sa.com/api/products/{productId}/custom

روابط التصنيفات: /products?category=16. تفاصيل المنتج: /products/20، وتجلب بياناته مباشرة من واجهة تفاصيل المنتج. الروابط القديمة /products/carpet و/products/blanket توجه إلى التصنيف المناسب. يتم التحقق من الاستجابة ومعرف التصنيف والأسعار قبل العرض، مع حالات تحميل وقائمة فارغة وخطأ وإعادة المحاولة. الصور الخارجية مسموحة فقط من مساري /storage/categories/ و/storage/products/ على نطاق الإدارة.

المنتجات والمقاسات تأتي من API. المقاس المخصص يدعم طولًا وعرضًا من ٠٫١ إلى ٢٠ متر والكمية من ١ إلى ٩٩. يتم جلب سعر المعاينة من POST /products/{id}/custom ثم إضافة القطعة إلى السلة عبر واجهة السلة. الأسعار النهائية والضريبة في السلة تؤخذ من GET /cart؛ لا تعاد حساباتها في المتصفح.

السلة لا تعتمد على المنتجات أو المقاسات الافتراضية ولا على البيانات القديمة في localStorage. إنشاء الطلب والدفع غير متاحين حاليًا، وأزيل كود الخصم التجريبي. رسوم التوصيل تعرض كقيمة تحدد عند إتمام الطلب بدل افتراض أنها مجانية.

تنظيم الربط:

- `lib/api/client.ts`: إرسال طلبات GET وPOST وإعداد اللغة والمهلة والتحقق من حالة HTTP وصلاحية JSON.
- `lib/api/shiny-carpet.ts`: مسارات التصنيفات ومنتجات التصنيف وتفاصيل المنتج وحساب المقاس المخصص.
- `lib/api/validation.ts`: التحقق المشترك من الاستجابات والمعرفات وروابط الصور.
- `lib/categories.ts` و`lib/api-products.ts`: التحقق من البيانات الخارجية وتحويلها إلى أنواع الواجهة؛ نفس تحويل المنتج يُستخدم للقائمة والتفاصيل.
- `hooks/useCatalogApi.ts`: hooks جاهزة للتصنيفات ومنتجات التصنيف وتفاصيل المنتج، تستخدم `useApiResource` للتحميل وإعادة المحاولة وإلغاء الطلبات القديمة. لا يوجد تخزين مؤقت مشترك بين المكونات.
- `hooks/useCustomProductPrice.ts`: حساب سعر المقاس عند الإرسال، ومنع الطلبات المتزامنة وإلغاؤها عند مغادرة الصفحة وعرض أخطاء مناسبة بالعربية.

يمكن ضبط رابط API العام من `NEXT_PUBLIC_API_BASE_URL` في `.env.local`؛ الافتراضي هو رابط الإدارة أعلاه. المتغير عام ويُضمَّن وقت البناء، لذلك يلزم إعادة البناء بعد تغييره ولا توضع به أسرار. تغيير خادم الصور يتطلب تحديث `images.remotePatterns` في `next.config.ts` والتحقق من الصور في `lib/api/validation.ts` أيضًا.

الطلبات ترسل `Accept: application/json` و`Accept-Language: ar` بمهلة ١٠ ثوانٍ. بيانات الشبكة تعامل كـ`unknown` حتى التحقق منها؛ أخطاء HTTP والردود غير الصالحة منفصلة، و404 لتفاصيل المنتج فقط تتحول إلى حالة منتج غير موجود. تُلغى الطلبات عند تغيير الصفحة أو التصنيف، ولا تستبدل الردود القديمة بيانات الطلب الحالي. طلبات المتصفح تتطلب سماح خادم API بـCORS لنطاق الموقع.

لتشغيل اختبارات الربط والأسعار والاستجابات غير الصالحة وإلغاء الطلبات: `npm run test:api`. الاختبارات تستخدم ردودًا محلية ثابتة ولا تعتمد على توافر API الفعلي.

## API السلة

`lib/api/cart.ts` يجمع الطلبات والتحقق من الأرقام والردود. `components/cart/CartProvider.tsx` يدير سلة الحساب وحالات التحميل والخطأ ومنع العمليات المتزامنة. كل الطلبات تذهب مباشرة إلى دومين الإدارة مع `Authorization: Bearer` و`Accept-Language: ar`.

- `GET /cart`: العناصر والإجماليات؛ `GET /count`: عداد السلة من `item_count`، دون افتراض أنه مجموع الكميات.
- `POST /cart/add`: يرسل `product_id` و`quantity`؛ المقاس الجاهز يضيف `product_size_id` والأبعاد المتاحة، والمخصص يرسل `length` و`width` دون `product_size_id`.
- `POST /cart/item/{cartItemId}`: يرسل `quantity` باستخدام FormData.
- `DELETE /cart/{cartItemId}`: حذف عنصر بمعرّف سطر السلة، وليس معرّف المنتج. `DELETE /cart`: إفراغ السلة.

بعد كل تعديل ناجح يتم تحديث GET /cart وGET /count. قيمة `price` للسطر تشمل الكمية فلا تضرب فيها ثانية. `cart_subtotal` و`vat_percentage` و`vat_amount` و`cart_total` هي المصدر المعتمد للأسعار. لا يضاف عنصر محليًا قبل نجاح API. إذا نجح التعديل وفشل التحديث، تظهر إعادة محاولة للجلب فقط، ولا يعاد إرسال الإضافة حتى لا تتكرر القطع.

السلة تفصل بين الحسابات، وتُلغى الطلبات القديمة عند الخروج أو تبديل الجلسة. غير المسجل ينتقل للدخول قبل الإضافة ثم يعود لصفحة المنتج. تغيير المقاس لعنصر موجود يتطلب حذفه وإضافة المقاس الجديد؛ لا توجد واجهة تعديل مقاس ضمن الواجهات المقدمة.

الاختبارات: `npm run test:cart` و`npm run test:cart:browser`. اختبار المتصفح يعترض كل واجهات API ويستخدم بيانات محلية فقط، ويغطي الإضافة بمقاس جاهز ومخصص والكمية وفشلها والحذف والإفراغ والعداد وانتهاء الجلسة وتجاهل البيانات القديمة.

## API العناوين

`lib/api/addresses.ts` يتحقق من عقود العناوين ويحوّل أسماء الحقول، و`components/addresses/AddressesProvider.tsx` يدير حالة عناوين الحساب والطلبات وإلغاء الردود القديمة. الطلبات مباشرة إلى `https://admin.shinycarpet-sa.com/api` مع التوكن واللغة العربية.

- `GET /addresses`: قراءة `data.addresses` وتحويل المعرّف والأسماء والإحداثيات والملاحظات والعنوان الافتراضي دون اختراع معرّفات المناطق من الأسماء.
- `POST /addresses`: إرسال `title` و`street` و`building_number` و`floor` و`apartment` و`details` و`notes` و`lat` و`lng` ومعرّفات المناطق.
- بطلب المستخدم، الإضافة تستخدم مؤقتًا `governorate_id: 1` و`area_id: 1` و`district_id: 10`. القيم مجمعة في `TEMPORARY_ADDRESS_LOCATION_IDS` إلى أن تتوفر واجهات قوائم المناطق الحقيقية. كتابة أسماء المناطق في النموذج أو اختيار الخريطة لا يستنتج معرّفات API.
- `PUT /addresses/{id}`: إرسال JSON مع الأسماء `governorate_name` و`city_name` بدل المعرّفات، كما في العقد المقدم. تُعرض القيم الراجعة من الباك إند حتى لو اختلفت عن المدخلات.
- `DELETE /addresses/{id}`: الحذف بعد تأكيد النافذة؛ الفشل يبقي العنوان ويعرض الخطأ. تعاد قراءة القائمة بعد كل تعديل ناجح، وإذا فشل الجلب التالي فإعادة المحاولة تعيد GET فقط.

إضافة عنوان أو تعديله من صفحة الشراء يفتح النموذج الكامل بالخريطة، ثم يعود إلى `/checkout?address={id}` لاختيار العنوان المحفوظ. تتطلب الصفحات تسجيل الدخول، وتُمسح عناوين العرض عند الخروج أو انتهاء الجلسة دون حذف عناوين الحساب من الباك إند. السجلات المحلية القديمة لا تُعرض كعناوين للحساب.

الاختبارات: `npm run test:addresses` و`npm run test:addresses:browser`. اختبار المتصفح يحتاج التطبيق على 3107 وPlaywright وEdge، ويعترض جميع طلبات API والموقع ببيانات محلية؛ لا يعدل عناوين حقيقية.


### إعدادات الموقع وحالات الطلب

تُحمّل بيانات التواصل والسوشيال والسياسات وصور الإعدادات العامة من `GET /settings` بطلب عام مشترك، مع إعادة المحاولة عند الفشل وإخفاء القيم الفارغة. يبقى لوجو الموقع المحلي وألوان شايني كاربت ثابتين. صفحتا `/privacy-policy` و`/terms-and-conditions` تعرضان النص القادم من API دون تنفيذ HTML.

تدعم الطلبات مراحل العمل المسجلة في `lib/order-status.ts`. تجمع صفحة الطلبات الحالات النشطة من `/orders`، ويحدد `delivered_to_customer` اكتمال الطلب، بينما تظل `paid` حالة نشطة. لا يظهر زر الإلغاء إلا في `confirmed`. التواريخ المعروضة من الخادم، دون اختلاق مواعيد للمراحل.
